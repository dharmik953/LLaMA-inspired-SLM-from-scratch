# 🧠 Small Language Model from Scratch — LLaMA-Style (124M)

> A decoder-only transformer built entirely from scratch in PyTorch, trained on TinyStories.  
> Upgraded from the original 2024 build that helped me land my first ML job.

---

## 🏁 Origin Story

In **2024**, I built the first version of this model from scratch — 6 transformer layers, ~30M parameters, no frameworks, just PyTorch and math. No tutorials followed end-to-end. Just reading papers and building.

That project got me my first job in ML.

Since then, I've revisited it — scaled it up to **124M parameters**, replaced every component with modern best practices (RMSNorm, RoPE, SwiGLU, KV-cache), and documented every design decision the way I'd explain it in a production code review.

This repo is the result.

---

## 📐 Architecture

The model is a **decoder-only transformer** in the style of LLaMA / Mistral / Qwen.  
Every component was chosen deliberately — not because it was default, but because it's what modern LLMs actually use.

| Component | Choice | Why |
|---|---|---|
| Normalization | **RMSNorm** | Fewer params, faster than LayerNorm, no quality loss (LLaMA) |
| Position Encoding | **RoPE** | Relative positions, zero learned params, better extrapolation |
| Feed-Forward | **SwiGLU** | Multiplicative gating — consistent quality gain at same FLOPs (Shazeer 2020) |
| Attention | **Flash Attention 2** | `F.scaled_dot_product_attention` — memory-efficient, faster on Ampere+ |
| Bias Terms | **None** | LLaMA convention — marginal quality win, plays better with weight decay |
| Weight Tying | **Yes** | Input embedding = output projection — standard practice |

## 🔧 Training Setup

Designed to run on a **single A100 80GB** with bf16 mixed precision and gradient accumulation.

| Hyperparameter | Value |
|---|---|
| Effective batch size | 256 sequences (64 × 4 grad accum) |
| Tokens per step | ~131K |
| LR schedule | Linear warmup → Cosine decay |
| Peak LR | 5e-4 |
| Min LR | 5e-5 |
| Optimizer | Fused AdamW (`fused=True`) |
| Gradient clipping | 1.0 |
| Weight decay | 0.1 (2D params only) |
| Total steps | 20,000 |

### Training Loop Fixes from the 2024 Version

The original had several bugs that are worth calling out explicitly — because getting these right matters:

- **Scheduler stepped per micro-batch** — with grad accumulation of 8, the LR decayed 8× too fast. Fixed to step per optimizer step.
- **`lowest_lr > base_lr`** — the cosine "decay" was actually an increase. Fixed.
- **`scaler.unscale_` missing** — under fp16 AMP, gradient clipping without unscaling clips the *scaled* gradients, not the real ones. Fixed.
- **Param-grouped weight decay** — norms, biases, and embeddings now correctly have `weight_decay=0`. The 2024 version decayed everything.

## ⚡ Inference

The `generate()` method uses a **KV-cache**, turning autoregressive decoding from O(n²) to O(n).  
The 2024 version re-encoded the full prefix on every token.

Also added:
- **Top-p (nucleus) sampling** alongside top-k
- **TTFT / TPS benchmarking** with proper CUDA synchronization and warmup runs

```python
generate_text("Once upon a time there was a pumpkin.")
# → coherent, grammatical children's story in <300ms on A100
```

## 📊 Dataset

**TinyStories** (Eldan & Li, 2023) — synthetic short stories generated by GPT-3.5/4.  
Small enough to train a model to convergence on one GPU. Rich enough that the model learns grammar, narrative structure, and basic causal reasoning.

Tokenized once to disk as `uint16` via `np.memmap` — the nanoGPT trick.  
Training reads random windows directly from disk. No RAM pressure regardless of dataset size.

## 🚀 What's Next (at Scale)

Things I'd add moving to multi-GPU:

- **Grouped-Query Attention (GQA)** — shrink KV-cache for inference without losing quality
- **FSDP or tensor parallelism** — standard multi-GPU training
- **RoPE base scaling** (NTK / YaRN) — extend context beyond 512 without retraining
- **Better tokenizer** — GPT-2 BPE is fine for English but suboptimal for code or multilingual data

---

## 📎 Honest Caveats

This model is small and TinyStories is a narrow distribution. The loss numbers aren't comparable to "real" LLM benchmarks — and that's fine. The point isn't the numbers.

The point is a clean, idiomatic, end-to-end implementation of the modern pre-training recipe — architecture, data pipeline, training loop, inference, and export — at a scale you can actually run on one GPU and read in one sitting.
